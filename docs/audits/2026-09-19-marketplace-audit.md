# Marketplace compatibility and repository audit

Date: 19 September 2026. Baseline: `9f6ec40532b6245611b5826f244e9b7f457f7419`. Review branch: `fix/chatgpt-marketplace-audit`.

## Executive conclusion

The reported sync failure is explained by `marketing/.mcp.json`: its top-level `$comment` is rejected by the importer and its server map is empty. Removing that unused file fixes the identified source-level blocker. The broader review found additional packaging, setup, calculation, API, parsing and workflow defects; these are addressed below. A real ChatGPT workspace resync is still an acceptance step, not something static checks can prove.

## Scope and assurance boundary

The baseline inventory comprises 927 repository files (the temporary audit export workflow made the intake snapshot 928), five plugins, 120 skills and nine Startups orchestrators. All tracked paths were inventoried and all skill metadata, packaged support references, JSON/YAML and Python syntax were structurally checked. Executable helpers, manifests, CI, installation paths, orchestration and high-risk numerical/provider workflows received targeted source review and regression tests. All 69 Startups skills are classified below. This is not a claim that every narrative assertion, third-party dependency, optional clustering path or model behaviour has been exhaustively verified. No finite audit establishes that all possible bugs have been found.

No live credentials, paid API calls, production database mutations, provider deployments, merges or public releases were performed by this audit. The source-export workflow was temporary and is removed from the final tree.

## Changes and migration

- Retain all 69 Startups skill IDs and all nine optional Claude agent recipes. No entire skill was proved obsolete from usage evidence.
- Native OpenAI catalogues/manifests/UI are generated from the existing source metadata; there is one instruction tree.
- Retire empty MCP/settings files, broken lifecycle hooks and duplicate command registrations. `seo-setup` and `seo-status` become ordinary skills.
- New workspaces use `.project/plans/startups/<slug>/`; verified legacy Memex workspaces stay in place.
- Setup is explicit and persistent, not a session-start download. Some optional workflows still need dependencies or authorised connectors.
- Calculator JSON contracts change: exact CVP values are separate from ceiling unit counts; gross BCR is null for net-only inputs; schema reports coverage, not conformance. Update consumers that assumed the old semantics.

## Validation

Local run: **116 passed, 4 skipped** using `python -m pytest tests -q`. Three SQL integration cases need an explicit temporary PostgreSQL DSN; one JSON-LD extraction case needs selectolax. The CI definition installs these and starts PostgreSQL 17. Current remote results are recorded in the PR; do not infer a CI pass merely from its configuration.

Packaging checks: `python scripts/sync-openai.py --check`, `python scripts/check-portability.py`, `node scripts/check-versions.mjs`. The local static checker is repository-specific and is not an official importer. The official Claude CLI is invoked in CI; it is unavailable in the local audit container.

Tests cover input boundaries, retention and break-even arithmetic, CBA labels/PI, cohort query generation, credentials, account-isolated cache keys, mocked DataForSEO task errors, Lighthouse arguments, workspace idempotence/preservation, tokens, disabled pipeline configuration, median calculation, Markdown sanitisation, setup recovery, version regression and packaged metadata. The focus-file test deliberately isolates a pure function; it does not execute the heavyweight semantic-clustering pipeline.

## Remaining risks and prioritised improvements

1. **Host acceptance and model evaluation (high priority).** Perform real ChatGPT sync, trigger selection and representative workflows in hosted and local contexts. Existing evaluation YAML is not evidence of actual model runs. Add reproducible outputs/verdicts for every workflow family, especially negative evidence and missing connectors.
2. **Reduce Startups overlap without breaking IDs (high priority).** Several wrappers split one process into tiny skills. Consolidate internals and keep aliases for a deprecation window, guided by usage and blinded output evaluations. See the matrix below; candidate overlap is not established obsolescence.
3. **Unify state and write semantics (high priority).** The runtime guide repairs external dependency assumptions, but many legacy templates still use Memex terminology. A future versioned venture schema plus shared read/update helpers would reduce instruction drift. Migrate only with explicit consent and backup.
4. **Provider-neutral planning (medium priority).** Supabase and Cloudflare recipes remain useful specialisations, not universal dependencies. Consider an optional engineering pack to reduce discovery noise for founders who need only discovery/experiments. Do not duplicate the separate John OS repository.
5. **Clustering reproducibility (medium priority).** Heavy optional models, corpus downloads, rendering and the entire vendored engine are not end-to-end tested here. Pin reviewed dependency/model versions, add small gold datasets, deterministic seeds, memory limits and an explicitly offline TF-IDF path.
6. **External API and crawler hardening (medium priority).** Mocked contracts do not prove account permissions, rate limits or current provider responses. Add opt-in contract tests with a spend ceiling, request budgets, retry/backoff and bounded sitemap recursion. Review credentials through an actual secret manager where available.
7. **General-purpose limits (medium priority).** Pipeline validation is a heuristic checklist, JSON-LD is field coverage, the token converter supports a subset, and IRR uses a finite bracket. Keep these limits visible; replacing them with full schema/financial engines requires separate design and tests.
8. **Evidence quality and documentation (medium priority).** Avoid arbitrary traffic-light gates, universal interview thresholds and unsupported commercial benchmarks. The added source registry acknowledges missing lecture material rather than fabricating precise citations. Remaining templates should be reviewed against actual contemporary use cases.
9. **Supply-chain assurance (medium priority).** CI dependencies and official validator are not fully hash-locked. Add pinned action SHAs, reviewed lock constraints, dependency scanning and release provenance in a dedicated security maintenance change. No claim of a complete dependency-vulnerability scan is made.

## Startups simplification plan

Best candidates: combine divergent/convergent/six-ways ideation; use canvas create/update/link/review modes; combine competitor evidence-to-positioning; unify measurement plans and event contracts; use conceptual/physical/migration data-design modes; and move provider-specific deployment details behind one deploy-planning entrypoint. Keep interview collection distinct from synthesis and preserve experimental design versus observed readout. Retain `venture-init`, `venture-status` and `phase-router` as clear top-level entrypoints.

Use a staged migration: baseline evaluations first; share internal references/helpers; add mode-based entrypoints; keep existing aliases; then measure routing confusion and output quality before retiring anything. A proposed target count would be a design choice, not evidence that a specific number of skills is redundant.
